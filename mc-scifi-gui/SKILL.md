# MC 科幻 GUI 设计与实施

为 Minecraft 模组界面做科幻风视觉升级的完整方法：设计语言（基于 Chris Noessel
《Make It So》与 Territory Studio 的影视级科幻界面方法论）+ MC/NeoForge 技术红线
（整数像素、渲染顺序、owo 布局陷阱——全部来自 AE2 Intelligence 项目的实锤教训）。

## 一、设计原则（先于装饰）

1. **可用性优先于氛围**：科幻 UI 的经典悖论是"透明全息牺牲可读性"。层级、反馈、
   状态可见性先立住，发光和透明只做强调层，永远不承载关键信息。
2. **叙事内一致性（diegetic）**：界面属于游戏世界——配色与模组主题绑定（ME 网络
   = 青/紫能量感），装饰元素要有"这台机器在运行"的语义（扫描线=数据处理、
   呼吸灯=在线状态、角标框=锁定/选中目标）。
3. **克制的动效**：呼吸（2s 正弦）、扫描线（>3s 慢速）、悬停发光增强。绝不用
   快闪/高频动画——玩家会盯这个界面几分钟，动效是背景噪声不是主角。
4. **色板纪律**：主色 1 + 底色 1 + 语义色 3（成功/警告/危险）+ 点缀 1。
   经典科幻组合：深空底(#0A0E14 系) + 青主色(#00E5D0 系) + 数据绿 + 琥珀警告 +
   警红。主色饱和度可以高，但只在描边/文字/高亮——大面积底色必须暗（≤20% 亮度）。
5. **细线几何**：1px 描边、四角角标（bracket corners，只画四角不画满框=科技感
   最强的单一元素）、细分割线。粗边框=工业感，细线+角标=仪器感。

## 二、MC 技术红线（违反必翻车，全部有实锤）

- **整像素对齐**：所有 fill/blit 坐标必须整数；浮点居中的 0.5 偏移在整倍缩放下
  NEAREST 采样丢像素行（图标右下缝隙实锤）。
- **图标尺寸量化**：`round(16×zoom)`，zoom 有下限；原点对齐整数像素。
- **渲染顺序 = 画架算法**：底色→框→内容（图标/文字）→角标→悬停层。平面贴图
  （查看器渲染器内部是 blit）被后画的框盖住=空白框实锤；物品图标靠 3D 深度幸存
  是巧合不是保障。
- **JEI 渲染器无坐标参数**：`IIngredientRenderer.render(guiGraphics, ingredient)`
  画在 pose 原点——必须先 `pose.translate(x, y, z)` 再调；z 提升（如 100）让图标
  浮于框之上。
- **owo 布局**：流式布局 + 全定宽（`Sizing.fixed`），NEVER 手工 absolute 算坐标、
  NEVER `Sizing.fill()` 弹簧占位（同排按钮被推出面板实锤）。绝对定位仅限两类：
  画布角落悬浮单元素、**铺底装饰层**（HoloPanelDecor 类背景装饰必须
  `Positioning.absolute(0,0)`——作为流式子件会占满整个面板高度，把真实内容
  全部挤出面板底部，实锤"元素全没了"）。
- **owo 悬停只认最深层命中**：容器被盖满子件时 mouseEnter 不触发。自绘单字/
  单图标按钮用无子件组件（悬停归自己）；容器+子件要双侧订阅。
- **`render` 覆写签名**：partialTick 是 `float`（写成 int = 静默失效无任何征兆）。
- **javadoc 里禁止出现 `*/` 子串**：如 `Toggle*` 枚举写法会提前终止注释、编译炸。
- **改视觉必须重启游戏验证**：进程不换改动不生效；让用户 F2 截图到 run/screenshots/
  读像素，一次复现一次收敛。

## 三、实施清单（AE2 Intelligence 结构，同类项目同构）

1. **UiStyle**（视觉常量集中地）：新色板命名常量，旧常量语义化替换（不逐处改 hex）。
2. **TreeGraph.Style**：连线/悬停/描边色注入式更新。
3. **屏幕自绘段**：面板底（可加细网格底纹：每 8px 一条 4% 透明度横竖线）、
   四角角标框（fill 四角 L 形各 5×2px）、标题栏（发光主色文字+下方 1px 分割线）。
4. **动效**（有 dt 渲染循环里做）：定义框呼吸已有先例（正弦 alpha）；悬停发光
   = 描边色亮度插值；扫描线=面板内 1px 横线以 >3s 周期下移（alpha 8%）。
5. **验证**：重启 → 各缩放档（0.6/1/2）像素截图检查 → 深色/亮色物品图标对比可读性。

## 四、系列一致性铁律（新物品属于既有系列时，各种方面都相同）

给既有系列的物品家族（AE2 存储元件、原版工具档位等）新增同类物品时，
**所有用户可见面向必须与系列兄弟一致**——不许给系列已标准化的东西自造格式
（智能物品存储元件实锤：自写"已用 x/x 字节"tooltip 被用户否决
"你的 tooltip 应该和 ae 系列的同类型物品相同"）：

1. **tooltip**：复用系列自家的助手与翻译键，逐字节同款。AE2 元件即
   `Tooltips.bytesUsed(...)` + `Tooltips.typesUsed(...)`
   （`appeng.core.localization.Tooltips`）——文案/数字格式/比率配色全部继承；
   物品专属数据行排在其后、风格随行；使用说明进指南（GuideME）不进 tooltip。
2. **图标/贴图**：像素级衍生自家族资产——同外壳、同剪影、同光照，只改区分
   元素（AE2 五档元件整图只差核心色像素，新档=把核心色换成无人使用的颜色，
   一眼同系列一眼可辨）。资产非自有时把衍生关系登记进项目
   THIRD-PARTY-NOTICES。
3. **命名与语言**：跟随系列命名惯例（档位/前缀模式），概念不另起名。
4. **GUI 行为**：指南查询键、JEI/EMI 处理、工作台/元件座兼容等与兄弟物品
   完全同表现。
