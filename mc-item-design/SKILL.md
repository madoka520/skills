# MC 物品设计：参照优先（配方与功能）

给模组新增物品（或改配方/改行为）时，**配方和功能优先参考模仿现有的物品，而不是
自己创新**。先找"最接近的现有同类"（同系列，或其它模组的同类），拆解它的结构再
动手——把"聪明"用在差异点上，不重造惯例（智能存储元件配方三轮返工实锤）。

## 一、配方与定价：先照搬结构，再表达溢价

1. **先拆参照物**：动手前把参照物的配方 JSON / 行为代码读一遍（拆 jar 看 data/
   与源码，不靠记忆）。AE2 元件 = 外壳 + 对应存储组件（价格由组件承载）；
   档位 ×4 = 低档元件 + 3× 同档组件——**价格严格按数值档位成比例**，不拍脑袋
   （实锤："配方的价格不合理，应该按它的存储字节来算，可以参考别的存储元件的
   配方"）。
2. **多配方形态照家族先例**：同族有几种配方就做几种，形态照抄——appmek 化学品
   元件 = 外壳+组件两件套直接合成 + 独立升级链，零附加材料（实锤："他们的配方
   都是有两种的，你模仿也模仿不对"）。
3. **溢价只用一种新材料表达**："高级版"用一处材料替换说清楚（智能外壳底排金属
   →紫水晶），**绝不叠加家族里不存在的花样**——用了高级外壳就不必再加处理器
   （实锤："都是智能外壳了就不用加智能处理器了啊"）。
4. **网格放不下就分档升级**：高数值档位用"低档物品 ×N 升级"的链式结构；必要时
   用条件配方（`neoforge:conditions` 的 `mod_loaded`）接入其它模组的更大规格
   材料补直接合成（如 MEGA 大组件——注意 maven slug ≠ modid）。
5. **升级链不吞数据**：消耗"承载内容的物品"的配方必须自定义 Recipe 类把输入的
   数据组件搬到结果（原版配方静默丢输入组件，满物品被升级吃掉是灾难）。

## 二、功能与行为：先模仿后创新

找最接近的现有物品，逐项对照它的行为细节——收什么/拒什么/怎么升级/数据是否
保留/与哪些系统交互（工作台、查看器、指南）——对齐之后再把创意用在差异点上。
宁可像，不要另起炉灶。

## 三、Tooltip：先参照同类物品的现成文案

- 动手前先拆参照物 jar 看它的 lang 文件：顶级物品往往**没有 tooltip**（物品名
  即说明，如 Avaritia 寰宇支配之剑），或只有一句意象化短句（如中子锭
  "致密恒星之心，化为一锭。"、"尽量不要去想它。"）。
- 照此办理：功能说明绝不进游戏内——最多一句灰色格调短句，让玩家自己发现
  能力（实锤："你这两行依旧是废话啊 你为什么不参考一下寰宇支配者呢"）。
- 不罗列子功能、不写教学、不写实现细节、不逐行换色；完整机制放 README。

## 三点五、GuideME 指南页写作规范（AE2 附属）

写 AE2 指南页（`assets/<modid>/ae2guide/`，中英双语 `_zh_cn/` 镜像）时，**先拆官方
参照物再动笔**：AE2 本体 `assets/ae2/ae2guide/items-blocks-machines/storage_cells.md`、
MEGA `bulk_cell.md` / `storage.md` 是文体基准（智能存储元件指南被实锤"太口语化，
'规则一句话'都是什么啊"后提炼）。要点：

1. **开篇 = 定位段落 + 图廊**：一段陈述句说清"它是什么、解决什么问题、放在哪"
   （如"Storage Cells are one of the primary methods of storage… They go in Drives
   or Chests"），后接 `<ItemImage>` Row/Column 图廊——不写口号式比喻。
2. **配方一律 `<RecipeFor id>` / `<Recipe id>` 内嵌展示**，文字只补充机制
   （"旧组件退还""净花费为两档差额"），**永不**用文字罗列材料清单。
3. **交叉引用用 `<ItemLink id>`**（原生设备活链接），跨页面用相对路径 md 链接。
4. **表格只放数字**（容量/档位对照），规则与限制用正文列表分条陈述；公式放
   引用块（`> type limit = bytes × 8 ÷ limit`）；**禁止**"规则一句话：""想 X 就
   调 Y"这类总结段/口语指令（留给自己人聊天，不进指南）。
5. **分节结构**：工作方式 / 容量 / 合成 / 升级 / 部署——每节陈述事实与因果，
   问答腔（"九成是优先级没调"）改写成因果说明段落。
6. **frontmatter 硬约束**（缺一整页丢弃）：`navigation.title` 必填；`item_ids`
   列全本页物品（JEI 按 U 能跳转）；中英两份必须同构。
7. 口吻基准：技术文档陈述句。可以先写英文再回中文，避免中文口语习惯带进去。

## 四、动手前自查

- 参照物找到了吗？它的配方 JSON / 行为源码真读过了吗（拆 jar，不凭记忆）？
- 价格与数值档位严格成比例吗？
- 溢价是不是恰好一种材料替换？有没有家族里不存在的自创花样？
- 家族已有的配方形态（直接/升级/条件联动）齐了吗？
- 消耗承载内容物品的配方，数据保留了吗？
- tooltip 参照过同类物品的 lang 文案了吗？有没有多余的说明书式行？
