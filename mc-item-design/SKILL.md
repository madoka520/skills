# MC 物品设计：参照优先（配方与功能）

给模组新增物品（或改配方/改行为）时，**配方和功能优先参考模仿现有的物品，而不是
自己创新**。先找"最接近的现有同类"（同系列，或其它模组的同类），拆解它的结构再
动手——把"聪明"用在差异点上，不重造惯例（智能存储元件配方三轮返工实锤）。

## 一、配方与定价：先照搬结构，再表达溢价

1. **先拆参照物**：动手前把参照物的配方 JSON / 行为代码读一遍（拆 jar 看 data/
   与源码，不靠记忆）。AE2 元件 = 外壳 + 对应存储组件（价格由组件承载）；
   档位 ×4 = 低档元件 + 3× 同档组件——**价格严格按数值档位成比例**，不拍脑袋
   （实锤："配方的价格不合理，应该按它的存储字节来算，可以参考别的存储元件的
   配方"）。
2. **多配方形态照家族先例**：同族有几种配方就做几种，形态照抄——appmek 化学品
   元件 = 外壳+组件两件套直接合成 + 独立升级链，零附加材料（实锤："他们的配方
   都是有两种的，你模仿也模仿不对"）。
3. **溢价只用一种新材料表达**："高级版"用一处材料替换说清楚（智能外壳底排金属
   →紫水晶），**绝不叠加家族里不存在的花样**——用了高级外壳就不必再加处理器
   （实锤："都是智能外壳了就不用加智能处理器了啊"）。
4. **网格放不下就分档升级**：高数值档位用"低档物品 ×N 升级"的链式结构；必要时
   用条件配方（`neoforge:conditions` 的 `mod_loaded`）接入其它模组的更大规格
   材料补直接合成（如 MEGA 大组件——注意 maven slug ≠ modid）。
5. **升级链不吞数据**：消耗"承载内容的物品"的配方必须自定义 Recipe 类把输入的
   数据组件搬到结果（原版配方静默丢输入组件，满物品被升级吃掉是灾难）。

## 二、功能与行为：先模仿后创新

找最接近的现有物品，逐项对照它的行为细节——收什么/拒什么/怎么升级/数据是否
保留/与哪些系统交互（工作台、查看器、指南）——对齐之后再把创意用在差异点上。
宁可像，不要另起炉灶。

## 三、动手前自查

- 参照物找到了吗？它的配方 JSON / 行为源码真读过了吗（拆 jar，不凭记忆）？
- 价格与数值档位严格成比例吗？
- 溢价是不是恰好一种材料替换？有没有家族里不存在的自创花样？
- 家族已有的配方形态（直接/升级/条件联动）齐了吗？
- 消耗承载内容物品的配方，数据保留了吗？
