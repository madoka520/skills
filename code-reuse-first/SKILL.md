# 复用优先与强制拆分

写任何东西之前，按下面的顺序从上往下找,**找不到才往下走**。

## 第零步:过一遍相关 skill(写代码前必查)

写代码前先扫一遍已安装的 skill,与当前任务匹配的必须先加载再动手:

- **写 Vue 组件/store/hooks** → 先过 `vue-reactive-module-pattern`(f/s 骨架、箭头函数、reactive 结构)
- **写 UI 样式** → 先过 `madoka-ui-style`(令牌、动效、BEM-lite)和 `web-app-ui-habits`(user-select/cursor/过渡)
- **写 Go 后端** → 先过 `wails-dev`(bindings、命令环境)
- **改存量代码** → 先过 `preserve-existing-code`(旧代码注释保留)
- **做完改动** → 过 `git-habits`(自动 commit+push)

跳过这步直接写 = 复犯(2026-10-12 已三次:Pinia 单例、手写按钮、Vue 骨架不符)。

## 取用优先级

1. **依赖库层**:组件库、工具库、框架与语言标准库(如 @madoka520/vue-ui、@madoka520/vue-utils、VueUse、Go 标准库)。库缺能力时,**首选给库加配置项或新能力并发版/提交**(遵循 CSS 变量配置化、默认值保持旧行为的模式),而不是在使用方手写绕过
2. **项目封装层**:项目里已封装的组件(app 的 `_components/`、全局 `components/`)、hooks(`useXxxStore` 等)、utils/service 里的现成函数 —— 存在就直接用,**同形态绝不写第二遍**
3. **最后才自己写**:动手前必须已确认上面两层都没有;写完发现是通用形态,反哺回库或公共模块

## 函数同样适用

- 写新函数前先搜项目里有没有同职责的:utils、hooks、service 方法、组件库导出的工具
- 复制粘贴一段已有逻辑之前,先想抽成公共函数放哪一层(库 → 项目公共 → 本模块)
- 同一个业务动作(删除确认、格式化、URL 拼接)只允许存在一个实现

## 必须拆分

- 出现可独立的视觉块(弹窗、工具栏、下拉、空态、列表项…)就拆成组件;独立职责的逻辑块拆 hooks/工具函数/服务模块
- 页面/入口文件收敛为「组装 + 少量胶水」;**一个文件三四百行就是拆分信号**
- 不要在一个文件里堆一大堆代码——长文件是没拆分的症状,不是本事
